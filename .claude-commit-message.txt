Three deployments failed all day and nothing said so

Every ship today - the board reorder, the acceptance letters, and the fix a
parent was waiting on - pushed to GitHub, reported "Shipped. Vercel is
building", and then failed to build. Production has been serving d7c0690 from
last night since 10:50 this morning. Lisa Roy retried her application after
the fix was "shipped" and got the identical error, because the fix was never
deployed.

WHAT BROKE IT. The board reorder took `committee_review` off the board, and
`validate-admissions-registry.mts` asserts that committee_review can reach
accepted, waitlisted and declined. That check fails, `npm run build` exits 1,
and the deployment dies at 10 seconds.

The invariant is right and stays. A pipeline whose last working stage cannot
reach an outcome traps families. It was simply pointed at the wrong stage: the
decision is made at `shadow_day_completed` now - that is where the
accept-or-deny gate opens and where the board's Decision column sits - so that
is the stage it asserts about.

WHY IT WAS INVISIBLE FOR THREE SHIPS, which is the part worth keeping.

  npx tsc --noEmit        passes
  npx vitest run          passes, 596 tests
  npm run build           FAILS

Only `npm run build` runs validate:admissions, and only Vercel runs
`npm run build`. The ship script checks types and tests, then pushes, then
prints "Shipped. Vercel is building" - which is a statement about what was
started, not about what happened. I read it as success three times and never
opened the deployment. That is the house pattern with the roles reversed: not
a silent failure this time but a confident success message standing in front
of one, and the cost was a family being told to try again on code that had
never shipped.

Verified before this commit, in this order: validate:admissions passed, then
the full `npm run build` completed with a clean route table.
