The inquiry is an inquiry again (and the wizard's leftovers)

TWO THINGS, because the first was only half shipped. Commit 40ea9907 carried
the wizard's three deleted FILES and nothing else: .\claude-ship.ps1 commits
the git index and does not add for you, and `git rm` had staged those three
itself. Every edit around them sat in the working tree. Production has had a
"Open multi-step application wizard" link on the parent portal pointing at a
route that no longer exists. That is fixed here.

── 1. The wizard's leftovers ────────────────────────────────────────────────

  constants.ts        APPLICATION_WIZARD_STEPS + ApplicationWizardStepId gone
  index.ts            their exports gone
  actions.ts          experienceSaveApplicationDraft, experienceSubmitApplication
                      gone (its only callers; the orchestrator methods stay -
                      they are service methods, not screens)

  portal page         the dead link gone

  screen catalog      its row gone

── 2. The inquiry is an inquiry again ───────────────────────────────────────

Jimmy, 29 September, with Georgia selected on the public form: "why does it
display the scholarship options and the rest of the application itself at
this inquiry phase." Then: "there should not be any scholarship information
included anywhere on any school's inquiry form." Then, twice: "these are the
only fields that should ever show for the inquiry/interest form for all
schools at all times."

ONE DEFINITION, TWO DOORS. /apply renders the inquiry phase. The invitation
link /apply/start/<token> renders everything. Jimmy: "no one ever submits an
application without us providing the url." Two definitions would drift apart;
one cannot.

  InterestFormPhase on sections AND questions. Default-closed at the front
  door: unmarked means application-only, so a section added in the form
  builder next month lands on the application, never on the page a stranger
  sees.

  isQuestionInPhase is asked by the RENDERER and by the VALIDATOR, the same
  way resolveStaticOptions is. Hidden on screen but required on submit is a
  form nobody can send; hidden but ACCEPTED is a rule anyone who can post a
  form can ignore.

  validateInterestSubmission takes `phase` as a REQUIRED input - a caller
  that forgets does not compile. submitPublishedInterestForm passes
  "inquiry", submitInterestFormForExistingLead passes "application". The
  server decides from which function ran, never from the request.

THE ESCAPE HATCH, and why this ships safely before the migration. A
definition where NOTHING declares a phase - every version through v31,
including the live one - is treated as all-inquiry, exactly how it behaves
today. Without it, this deploy would serve an EMPTY inquiry form to every
family until 454 ran.

MIGRATION 454 IS NOT RUN. It is in the repo, tested against a local Postgres
16 seeded with a faithful replica of v31 (65 questions, 12 sections), and it
waits for Jimmy's word. 21 inquiry + 44 application = 65; a re-run publishes
nothing; v31 archives whole.

Tests: the-inquiry-is-twenty-fields.test.ts pins the escape hatch, the
default-closed rule, the override in both directions, and the regression that
would take the whole form down - an inquiry refused for the 44 required
questions it never showed. 21 existing validateInterestSubmission call sites
across six test files now name their phase.
