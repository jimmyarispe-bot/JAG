A test file, and one finding that is not about the skip button.

── WHY THE SENT ROW PROVES NOTHING ─────────────────────────────────────────

Skip next stage was pressed twice against a real child this evening and both
presses did exactly what they should. Reading the sent letter back out of
admissions_communications afterwards showed the URL and NO LABEL, which looks
like a fault and is not one: the row keeps the TEXT body with merge fields
resolved - a bare link. The label is applied by renderLetterHtml when the HTML
is built, so the only way to answer "does the button say the right thing" is
to render it. That is what this file does, against both bodies exactly as
migration 557 left them.

Four tests: the skip button renders on the decision gate letter, its own href
is the real token and not the case-page fallback, it is a button and not a
bare underlined link, and on the inquiry notice it is ADDED - "this is in
addition to whatever button/decision is already there" - with the existing
button untouched.

── THE FINDING, AND IT IS FROM THIS MORNING'S SHIP ─────────────────────────

Jimmy asked on 15 October for "send the link to - send schedule interest
meeting/conversation link". BUTTON_LABELS.interest_link_action was shipped
saying exactly that, in 3c908c8e. IT DOES NOT REACH HIM.

inquiry_staff_alert wraps the merge field in its own anchor:

    <p><a href="{{interest_link_action}}">Send them the interest meeting link</a></p>

and letter-html deliberately keeps an author's anchor text - "a link somebody
wrote an anchor around is a decision". So the button in that letter still
reads the old words, and three of the four labels he asked for landed while
the fourth did not.

It is recorded here as a PASSING test of what is true, not a failing test of
what should be. Fixing it means editing an approved letter body, which is his
call and not something to slip in beside another feature. When he says the
word, one migration changes the anchor text and this expectation inverts.

── A WRONG ASSERTION, CAUGHT BY RUNNING IT ─────────────────────────────────

The first version asserted the letter contained no /dashboard/admissions/cases/
URL, meaning to check the skip link had not fallen back to the case page. It
failed, correctly: {{decisions_link}} resolves to
/dashboard/admissions/cases/<id>?section=decisions, so that string is in a
letter where nothing is wrong. The check now reads the skip button's OWN href.
The sent letter showing that exact URL had already been read an hour earlier
and the assertion was written anyway.
