fix(finance): the line and the week agree

Jessica Price, 9 October 2026, looking at her own screen:

    1:1 Tutoring Structured Literacy    9:00am    $35.00
    1 student - $35.00 for this class
    Monday October 5                              $35.00

    This week so far        $20.00
    [ Submit this week - $20.00 ]

Same class. Same screen. Two answers.

WHY

week-view.ts priced each LINE from the catalogue rate, then built the input
for weekTotals by mapping the same rows into WeekClassEntry - a shape that
carried neither baseCents nor missed. So weekTotals re-priced every class
from the structuredLiteracy boolean alone and reached a different number.

isStructuredLiteracy uses startsWith. "1:1 Tutoring Structured Literacy"
does not START with "Structured Literacy", so the boolean was false and the
total priced it at the $20.00 default while the line read $35.00 from the
catalogue, where the rate is correctly recorded.

Two courses are affected, and it is not only Jessica:

    COURSE                             LINE     TOTAL COUNTED
    1:1 Tutoring Structured Literacy   $35.00   $20.00
    1:1 Tutoring Craig & Ivy           $30.00   $20.00

    Craig Mann    week of 29 Sept   APPROVED   5 classes   short $50.00
    Holly Medlong week of 29 Sept   APPROVED   2 classes   short $30.00
    Jessica Price week of 5 Oct     open       1 class     short $15.00

Craig's and Holly's weeks were approved and paid at the short figure. That
is $80.00 owed, and it is Jimmy's call how to settle it - not corrected
here. The September network total of $6,985.00 reported earlier the same
evening carries the same $80.00 shortfall, because the frozen figures were
frozen from the broken total.

AND A SECOND ONE, FOUND WHILE READING THE FIRST

The same map dropped `missed`. A class marked "I missed this" is struck
through and shows $0.00 on the line - and was still being added to the week
total. Shipped in 2428941f yesterday; teacher_hourly_claims-style luck meant
nobody had pressed the button yet, so it had never been seen. It would have
been, this Friday.

THE FIX, AND WHY IT IS SHAPED THIS WAY

WeekClassEntry now carries baseCents, perAdditionalCents and missed, and
weekTotals applies the same two rules the line already applied:

    if (entry.missed === true) continue;        // zero before the rate
    entry.baseCents !== undefined               // catalogue wins
      ? classPayAt({ ... })
      : classPay(entry);

Counting moved ABOVE the missed check on purpose. Who was scheduled and who
was away is a fact about the morning and stays true whether the class paid
or not - a class she missed with six children booked is still six children
who turned up to nothing.

THE REAL FIX IS THE TEST. Two code paths pricing the same class will drift
again; the next divergence will be a field nobody thought to add to the map.
So the new tests assert an invariant rather than three examples:

    sum of line amounts === classCents

across a catalogue rate the name would have priced differently, a flat rate
with no per-student amount, a missed class, a missed class's children still
being counted, and a mixed week that also balances by campus.

47 tests pass, up from 42. Typecheck clean.

NOT FIXED HERE. isStructuredLiteracy is now vestigial wherever the catalogue
rate is present, and it is still consulted when it is absent. A rate decided
by whether a course NAME begins with two particular words is the same fault
one layer down - rename a course and somebody's pay changes. The catalogue
is the answer and classPay's boolean should go. That is a change with a
screen behind it, and this was found with a teacher already looking at the
wrong number.
