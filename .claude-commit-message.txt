the sidebar could not see who you are

"Alright so this is correct but I don't have any admissions information?!" —
Jimmy, looking at a sidebar with six modules where there should be thirteen.

WHAT WAS MISSING

Admissions. Student Success. Scholarships. Finance. Workforce. Scheduling.
Teacher Studio. Gone from the sidebar — for the Founder, and for every School
Leader. What remained was Families, Communications, Workflows, Calendar and
Documents, which is not a random six.

THE SHAPE OF IT

module-visibility hides every module naming a required permission unless the
viewer holds one of them, and it fails CLOSED on purpose. Its own comment says
why: "a page that could not work out who you are should not conclude you may see
the money."

That is right, and it is exactly why this hid so well. The list that answers
"who you are" was never passed. `permissions` defaulted to [] in DashboardShell,
again in DashboardChrome, again in Sidebar, and the answer for every viewer was
nobody. So the sidebar rendered precisely the modules that name no permission
and dropped every one that does.

Not a random six. The complement of the map.

  layout.tsx  ->  DashboardShell  ->  DashboardChrome  ->  Sidebar
                  permissions=[]     permissions=[]       permissions=[]

One line, three defaults deep, and no error anywhere. The pages themselves still
worked if you knew the URL, so nothing refused and nothing logged — it read as
data having gone missing rather than as a menu being hidden, which is why it was
reported as "where is my admissions information" and not as a navigation bug.

THE FIX

    permissions={ctx.permissions}

ctx already held them. The layout had ctx. It simply never handed them on.

WHY THE TESTS DID NOT CATCH IT

MODULE_REQUIRED_PERMISSIONS has its own test and passed the whole time. It
checks the map. Nothing checked that the list ever arrived, so the seam between
a correct rule and a correct caller was the one place with no cover. The new
tests hold the seam: one assertion per hop, plus the cost of an empty list
spelled out so nobody "fixes" this later by loosening the default instead.

Failing closed stays. The bug was never that [] hides things. It is that [] was
what the layout sent.
