a campus only jimmy can see

Jimmy, 11 October: "i want to create a universal account/login/system that i
can use to test everything a school leader sees, receives, does, etc. waiting
on them and having to work with them to workout the kinks in the jag is not
practical and very timeconsuming. i want to be able to do this myself."

Every end-to-end test this month has been run through a real campus, which
means a real school leader's inbox and a real family's pipeline, and three of
them ended with Danni reading letters about children who do not exist.

This adds a fifth campus - XXXXXXXX Test Campus - that exists only to be
tested through. Migration 538, already applied and verified, builds it as a
faithful copy of The Academy FL:
the same sixteen school-specific letters byte for byte, the same six programs,
the same fourteen checklist items, the same admissions settings, tours
switched on. One difference matters: every email it sends is addressed to
test.leader@theacademyway.org, which is Jimmy's own account.

The code change is one line of data. TOUR_CAMPUS_NAMES decides whether a tour
sits between the interest conversation and the application, and it is keyed on
the campus NAME because schools has no column that says what kind of school it
is. Without the new name on that list the test campus would route straight
past the tour - the longest step in the FL sequence, and the one the last two
weeks of work was about - and the test would prove nothing about the road a GA
or FL family actually walks.

One test refused the ship, and it was right to.

tests/unit/admissions/tour-step.test.ts asserts TOUR_CAMPUS_NAMES has length
2 - "is GA and FL, and only those two" - which is exactly the guard that
should exist on a list where adding a name silently changes which families are
asked to tour. It now asserts three, with the reason written beside it, and
adds the test campus to the campuses that run tours.

I had told Jimmy no test referenced that list. The grep that said so was run
under a timeout and was killed before it finished; I read its empty output as
an answer. Same class of mistake as reading an exit code through a pipe. The
sweep was run again to completion with the return code checked: that one test
file is the only place in tests/ that touches TOUR_CAMPUS_NAMES,
campusRunsTours or requireTourLink.

Checked, not assumed:

  - scoped typecheck of tour.ts, exit code read straight off tsc: clean
  - scoped typecheck of the test file against tsconfig.test.json: clean
  - every assertion the updated test makes, run against the built module:
    length is 3, the new name matches trimmed and in any case, HS, Virtual,
    "The Academy Mars", null and undefined all still read as no-tours,
    requireTourLink returns the tour link for the new campus and still
    refuses when the link is blank
  - all 16 FL templates read first: not one writes "The Academy FL",
    "Florida" or an address into its subject or body. Every campus-specific
    word in them is a merge field, so the copy needed no rewording.
  - templates resolve school-specific over org-level (engine.ts sorts null
    first, school last), so the copy is what the test campus will actually
    send - without it the campus would have inherited the generic org wording
    and the test would have read the wrong letters.

Two things this does NOT do, both deliberate:

  1. It does not touch the published interest form, version 39. That form's
     inquiry Program question filters its options by school id, so on /apply
     the test campus will offer only "Only Virtual" and the FL-specific
     application sections will not appear for it. Editing a form 146 real
     families have used is a separate change, for Jimmy to say yes to.
  2. It does not share test.leader@'s calendar with
     jimmy.arispe@theacademyway.org. The booking scan reads only the calendars
     in that account's calendarList, so until the share is accepted the scan
     reports this campus under campusesWithNoCalendar. That is a Google
     setting, not a database one.
